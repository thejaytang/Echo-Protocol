# 图灵迷局 改版简报 v2（Leader + PM + UI/UX 联合产出）

## 0. 诊断结论

现状不是"缺功能"，而是"视觉和体验没有兑现自己的设计规范"。证据：

1. `VISUAL_DESIGN.md` 明确要求深墨背景（`#101522`）+ 暖金（`#FFD46B`）+ 信号青（`#22D3EE`）+ 警示红（`#FF5F57`），构图是"暗色圆桌上的信号推理"。
2. 实际实现（`mirage-prototype/src/styles.css` 和生产端 `server/src/homePage.mjs`）用的却是米白背景 `#f6f2ea` + 单一橙色 `#f2a000`，视觉上是通用聊天/表单模板，没有青色信号层，导致所有信息同权重、没有悬念感。
3. `docs/UX_INTERACTION_AUDIT.md` 已经指出信息架构重复（五个入口抢首屏）、"怀疑程度"语义混用、揭晓页情绪最平等问题，但这些结论没有体现在 `mirage-prototype` 里。
4. 揭晓（Reveal）是"找AI"游戏情绪最高点，现状是全场信息密度最低、最像静态列表的一屏。

本轮目标：让 `mirage-prototype` 先兑现自己写过的设计规范和审计建议，做出有辨识度、有仪式感的版本，再决定是否移植到生产 `homePage.mjs` 和 iOS `MirageViews.swift`。

## 1. 视觉规格（UI/UX 部分，前端必须严格遵守）

### 1.1 色板（CSS 变量，替换 styles.css 现有取值）

```css
:root {
  --ink-900: #0b0f19;      /* 全局背景，比VISUAL_DESIGN更深一档增加层次 */
  --ink-800: #101522;      /* 主背景 */
  --ink-700: #161c2c;      /* 次级背景/大厅卡片 */
  --surface: #2a2d3d;      /* 卡片、气泡表层（Evidence surface） */
  --surface-raised: #343850; /* hover/active卡片 */
  --gold: #ffd46b;         /* 玩家可操作动作、阶段推进、奖励确认（Player agency）*/
  --gold-dim: #7a6636;     /* 金色的暗态/禁用态 */
  --cyan: #22d3ee;         /* 怀疑信号、线索、盯人、任务动作（Suspicion signal）*/
  --red: #ff5f57;          /* 倒计时风险、误判、举报、封禁（Risk）*/
  --text-primary: #f4f1ea;
  --text-secondary: #9aa0ae;
  --text-tertiary: #6b7280;
  --divider: rgba(244, 241, 234, 0.08);
}
```

- 大厅/战绩/我的可以比局内稍亮（用 `--ink-700`），但必须延续同一套金/青/红语言，不能引入米白或新的第三方色系。
- 禁止大色块装饰、禁止说明性长文案卡片堆叠在局内主视线上（`VISUAL_DESIGN.md` 第 8 节验收标准原样适用）。

### 1.2 构图规则

- 局内座位从"横向头像条"改为**弧形/环形排布**（模拟圆桌俯视），当前发言者座位有青色呼吸光环（CSS animation，2s 循环），我方"盯人目标"用金色描边，"怀疑标记"用青色描边——两者视觉必须可区分（回应审计里"盯人目标"和"怀疑标记"语义混用的问题，不能共用同一个选中态样式）。
- 阶段条（StageRail）：已完成阶段圆点为实心金色并有连接线；当前阶段圆点带脉冲发光动画（box-shadow 呼吸）；未来阶段为暗灰描边。不再是纯扁平数字圆点。
- 倒计时：不再是纯文本 `01:42`，外层包一个 SVG/CSS 环形进度条；剩余 <10 秒时数字和环变红并有轻微 scale 抖动（`--red`），制造紧张感。
- 首屏 2 秒识别原则：任何一屏必须能立刻看出当前处于"大厅 / 任务卡 / 讨论 / 投票 / 揭晓 / 复盘"哪个状态，不能靠说明文字判断。

### 1.3 三个关键仪式感时刻（本轮改造重点，优先级最高）

**A. 任务卡（新增，当前 prototype 完全没做）**

开局第一屏必须是任务卡弹层，不是直接进聊天室。四行固定结构：

1. 阵营/身份：侦探 / 人类卧底 / 伪 AI 真人 / AI（按角色区分标题："侦探任务" / "阵营任务" / "诱饵任务" / "伪装任务"，绝不能写"身份卡"）。
2. 目标：一句话讲清楚要做什么。
3. 赢法：投票阶段要达成什么结果。
4. 工具：证据笔记、起手句；高级模式追加阵营任务技能说明。

确认按钮为金色"确认任务"，点击后有短促收起动画（卡片向上收起，阶段条从"任务"点亮到"讨论"），不能只是弹窗消失。

**B. 揭晓（Reveal，现状最需要重做的一屏）**

从静态列表改为**逐位翻牌**：

1. 按"本局怀疑集中度"排序（复用玩家自己标记的怀疑数据即可，前端可用 mock 顺序），逐个座位揭晓，每次翻牌间隔约 400-600ms，身份光环从灰色过渡到揭晓色（人类=青绿描边，AI=红色描边+"AI"徽标轻微抖动进入）。
2. 全部翻完后，结果标题从底部升起（"你找出了隐藏 AI" / "伪装者逃脱了"），随后展示"查看复盘"主按钮。
3. 揭晓页新增一个"战报卡预览"迷你组件（见第 2.3 节），为后续分享做视觉埋点。
4. 允许用户点击跳过动画（一次点击直接展示全部结果），不能强制观看。

**C. 复盘（信息架构不变，视觉重做）**

保持现有信息顺序（结果一句话 → 我的任务结果 → 我的判断 → 复盘校准 → 投票板 → 身份和 AI 目标 → 关键证据时间线 → 局后处理 → 奖励 → 下一步），但视觉上改为可滚动的"时间线胶片"：关键判断点用青色标记，误判/被误导的点用红色标记，一眼看出转折点，不再是无差别的文本列表。

## 2. 产品/增长/商业化补充（PM 部分）

本轮只做三个新增点，克制范围，不新增游戏模式（M05/M07 等仍锁在 Phase 2 池，不进入本次交付）：

### 2.1 好友房邀请强化

等待页改为圆桌座位状态（已占用 / 等待中 / AI 补位三态可视化），邀请码做成大字卡片 + 一键复制 + "分享邀请"按钮，作为好友房这个"低成本传播"主路径的视觉强化。

### 2.2 首页信息架构简化（对应 UX_INTERACTION_AUDIT 建议，克制执行）

- 顶部三项统计改名为"识别率 / 完赛 / 可复盘局"，不要用"复盘查看"这类含混词。
- 新增极简底部 tab：开局 / 战绩 / 我的（三个即可，不做四 tab 实验）。本轮"战绩"和"我的"只需轻量占位屏（各自一个简单卡片列表即可），核心工作量集中在"开局"和对局全流程。
- 首页不新增赛季段位/排行榜三宫格，避免和审计报告里指出的"抢首屏"问题重复。

### 2.3 战报分享卡（新增组件，增长关键动作）

复盘页"分享战报"按钮点击后，展示一张可分享卡片预览：模式名、话题、结果一句话、1-2 条关键线索、"图灵迷局"品牌水印。**不得包含**用户 ID、房号、对局编号或其他玩家真实昵称之外的可识别信息（对局内其他玩家昵称展示需匿名化，例如替换为"神秘玩家 B"）。

### 2.4 商业化预埋（非强制付费，仅预告）

复盘页角落加一个"限定任务卡皮肤"预览徽标，点击弹出"即将上线"提示层，不接入真实购买流程，不做付费墙。这只是给用户建立"以后有换装内容"的预期，不影响 v1.0 核心体验。

## 3. 合规底线（红线，前后端都必须遵守，来自 PRD 和 VISUAL_DESIGN 验收标准）

1. 产品名只用"图灵迷局"；"找 AI"只能描述玩法目标，不能作为标题、按钮主文案；不使用"狼人杀"作为产品名或核心视觉符号。
2. "任务卡"不是"身份卡"；常规局显示"侦探任务"，高级局显示"阵营任务/诱饵任务"，AI 视角显示"伪装任务"。
3. 不做"举报单条发言"独立功能；举报/拉黑收敛在复盘页"局后处理"区域。
4. 起手句只能填入输入框草稿，不能代替用户直接发送。
5. 揭晓前不能展示系统自动生成的可疑分、真实角色推断分或 `strategyTag`；只能展示玩家自己标记的"我的怀疑标记"。
6. UI 文案不能出现"服务端 / 本地 / 模板 / 机制说明"等破坏沉浸感、暴露实现细节的词。
7. 截图/演示不能出现 debug、admin、localhost、占位域名或旧产品名。

## 4. 交付边界

- 本轮范围：仅 `mirage-prototype`（React + Vite 网页原型）。生产 `server/src/homePage.mjs` 和 iOS `MirageViews.swift` **本轮不直接大改**，待本原型跑通并经用户确认后再排期移植。
- 后端 `server/`：只在"战报分享卡""好友房邀请强化""权益预告"这三点确实需要新接口时，评估并做最小可行、可回滚的新增（新增文件/新增只读端点优先），不得改动 `security.mjs`、`moderation.mjs`、`appleAuth.mjs`、`wechatAuth.mjs`、`googleAuth.mjs`、`commerce.mjs` 中的鉴权/风控/支付核心逻辑。若判断不需要真实后端联调（前端可用 mock 数据完成本轮验证），应明确说明并只产出接口变更建议文档，不动生产代码。
