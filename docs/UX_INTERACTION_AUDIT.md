# 图灵迷局 UI/交互审计

审计对象：

- `server/src/homePage.mjs`
- `ios/Mirage/Mirage/MirageViews.swift`
- `Mirage_PRD_v1.0.md`

审计结论：现有实现已经覆盖了 **MVP** 需要的首页、开局、等待、好友房、局内、投票、揭晓、复盘、悬赏、榜单和我的等组件。已将首页主导航收敛为“大厅 / 战绩 / 我的”：榜单并入战绩，今日悬赏收敛到大厅/局后，背包装扮并入我的。后续仍应围绕“先上桌，再判断，再解释，再开下一局”的 **core loop** 继续减少冗余入口。

## 1. 证据地图

Web 端关键位置：

- `renderHome`：首页顶部、统计、未完成局、当前 tab 内容。
- `renderLobbyShortcuts`：大厅只在有可领奖励时露出今日悬赏提醒，不再重复放入战绩、榜单、任务快捷入口。
- `renderHomeNav`：底部三 tab：大厅、战绩、我的。
- `renderGame`：局内同时展示阶段、座位、话题、发言、行动区。
- `renderTaskCardOverlay`：任务卡以弹层阻断发言。
- `renderSuspicionMeter`：发言气泡里显示玩家自己的“我的怀疑标记”。
- `renderGameControls` / `renderRoleSkillPanel` / `renderVoteConfirm`：讨论、阵营任务技能、投票动作。
- `renderReplay`：结算、奖励、关键线索、举报、再来一局。

iOS 端关键位置：

- `HomeView` / `HomeTab`：底部三 tab 与首页内容结构。
- `LobbyShortcutGrid`：大厅内只保留可领奖励提醒，赛季和排行榜归入战绩。
- `GameView`：局内主结构。
- `TaskCardPanel`：任务卡。
- `RoomMessageBubble`：发言和 `strategyTag` 展示。
- `StageActionPanel`：证据笔记、阶段动作和投票入口。
- `VotingPanel`：候选人、信心值、确认投票。
- `RevealPanel` / `ReplaySummaryCard`：揭晓与复盘。

PRD 关键约束：

- **core loop**：聊天、怀疑、投票、揭晓、复盘、再来一局。
- 首页 **P0**：快速开始、模式入口、好友房入口、最近复盘。
- 局内 **P0**：任务卡、发言、证据笔记、投票、揭晓、复盘。
- 复盘 **P0**：身份总览、投票结果、AI 目标、关键发言、误判解释。
- 成长系统：v1.0 只展示基础识别分、完成局数、猜中次数、最近复盘，复杂段位进入 Phase 2。

## 2. 总体问题

现有 **IA** 有三套产品模型在抢首屏：

1. 游戏大厅：快速开始、3 人猎 AI、好友房、模式规则。
2. 成长看板：赛季段位、排行榜、今日悬赏、推理星、装扮。
3. 对局桌面：任务卡、座位、发言、证据、投票、复盘。

这三套模型都成立，但不应该同级展示。v1.0 的第一目标是证明用户愿意完成并重复一局，因此首页要服务开局，局内要服务判断，局后要服务解释和再开。榜单、悬赏、装扮可以保留，但应作为“完成一局后的反馈和奖励”，而不是和开局入口争夺用户注意力。

可执行方向：

- 首页从五 tab 降为三 tab：开局、战绩、我的。榜单并入战绩，任务改名“悬赏”并作为开局/局后卡片出现。
- 局内把“选中座位”拆成不同语义：讨论阶段是盯人目标，投票阶段是投票目标，不共用同一视觉状态。
- 复盘从“结果 + 几条线索”升级为“我投了谁、他是谁、我为什么对/错、哪条发言影响判断、下一局怎么做”。
- 所有局内推理线索必须遵守揭晓前信息边界。`strategyTag` 和系统推断的可疑程度不应在讨论阶段直接暴露。

## 3. 分模块审计

### 3.1 首页

现状：

- 顶部已经有玩家等级和三项统计。
- 大厅内又放了赛季段位、排行榜、今日悬赏三个快捷卡。
- 底部导航也有战绩、榜单、任务、我的。
- “线索”同时像复盘可用率、局后阶段名和推理证据，含义不稳定。

问题：

- 新用户完成引导后，首屏同时看到开局、段位、榜单、任务、好友房、玩法速览，主动作不够唯一。
- “战绩”和“榜单”都在讲赛季表现，“任务”和“我的”都在讲推理星、经验、装扮，重复明显。
- PRD 要求首页 **P0** 是快速开始、模式入口、好友房入口、最近复盘。当前榜单和背包装扮的权重高于 v1.0 需要。

建议：

- 已处理：大厅主路径固定为继续上一局、快速开始、3 人猎 AI、最近复盘/再来一局、好友房创建/加入。
- 顶部统计保留三项，但统一命名：识别率、完赛、可复盘局。不要用“线索”做统计标签。
- 大厅内删除“赛季段位 / 排行榜 / 今日悬赏”三宫格，改为局后或首屏下方的轻量提醒。
- 底部导航改为：开局、战绩、我的。若好友房是增长主入口，可以测试四 tab：开局、好友房、战绩、我的。

### 3.2 开局与模式选择

现状：

- 快速开始和 3 人抓伪装者作为公开匹配入口。
- M03/M04/M06/M08 已收敛到“好友房”区块内，先选好友房玩法，再创建房间；已有房号可直接加入。
- Mode sheet 展示人数、讨论、投票、流程、话题、规则和安全提示。

问题：

- Mode sheet 的信息完整，但没有把“怎么赢”提到与人数、时长同级。
- 等待页有刷新和切换入口，但没有明确“等多久算超时”和“是否会 AI 补位”。

建议：

- 已处理：开局入口统一为两类：公开匹配、好友房。公开匹配只露出 M01/M02，好友房区块内选择 M03/M04/M06/M08。
- 已处理：好友房玩法选择打开同一个 Mode sheet；加入房间作为独立输入。
- Mode sheet 固定四块：本局目标、怎么赢、流程和时长、话题与安全。
- 等待页增加清晰状态：已等待时间、还差几名真人、是否允许 AI 补位、超时后主按钮变为“改玩 2 人真假局”。

已处理：matchmaking ticket 现在返回 `createdAt`，Web 和 iOS 公开匹配等待页展示“已等待”，保留“还差真人”和 AI 补位说明，并在超过 45 秒后明确建议切到 2 人真假局或好友房；好友房等待超过 90 秒时提示先玩 2 人真假局或继续复制房号拉人。

### 3.3 局内

现状：

- 局内基础顺序是阶段条、座位、话题；讨论阶段先读发言再记录证据，表态、最终陈述、投票、揭晓/复盘阶段先显示行动或结果面板，再回看发言。
- 讨论阶段通过点座位选择盯人目标，再记录证据；需要确认细节时直接在聊天里发问。
- 进入投票阶段时，如果玩家讨论阶段盯过某人，Web / iOS 会显示“已沿用盯人目标”，并允许一键重选。
- Web / iOS 发言流不再展示揭晓前 `strategyTag`，只展示玩家自己的证据和线索标记。

问题：

- 话题卡、阶段提示、任务卡、行动面板都有指导文案，但没有形成一个“当前只做一件事”的行动焦点。

建议：

- 已处理：局内主结构按阶段分流。讨论阶段保留“发言流 → 证据动作”，表态、最终陈述、投票、揭晓/复盘阶段前置阶段动作或结果，规则和话题不占据主阅读位置。
- 已处理：讨论阶段使用“盯人目标”，投票阶段使用“投票目标”；进入投票时会显式提示“已沿用盯人目标”，并提供“重选”。
- 已处理：揭晓前隐藏服务端策略标签和系统判断分，只展示用户自己做过的证据和线索标记。
- 已处理：发言流支持用户把某条发言“标为线索”，而不是系统替用户标“可疑点”。

### 3.4 投票

现状：

- 候选人列表、信心值、确认归票、最终确认卡都已存在。
- 投票文案已统一为倒计时结束或全员交票前可修改，重复提交保留最后一票。
- Web / iOS 都展示 `voteState` 进度，投票后可看到已投目标、是否可改、还差几名真人交票。
- Web / iOS 在归票倒计时已结束时进入等待揭晓状态，不再展示可提交确认的投票按钮。
- 讨论阶段可把某条非自己发言“标为线索”，投票候选卡和复盘会展示“我标记的发言”。

问题：

- 已处理：投票页已带入“我的怀疑标记”“中段表态”“我标记的发言”和讨论阶段盯人目标，候选卡能直接看到本局判断链。

建议：

- 已处理：候选人卡展示三类证据：我的怀疑标记、中段表态、我标记的发言。
- 信心值保留，但解释为“用于复盘校准”，不要让用户以为会影响胜负。
- M01 已单独处理：2 人真假局的投票目标表达为“判断对方是 AI / 真人”，而不只是“投出某个座位”；其中 `abstain` 在该模式下表示判断对方是真人。
- 已处理：服务端在 `VOTING` 返回 `voteState.submittedCount` / `remaining` / `total`，Web 和 iOS 的投票状态显示“还差几名真人交票”，同时继续隐藏其他玩家具体投票目标。
- 已处理：服务端在 `messages[].reactionType` 返回当前用户的私有线索标记，Web 和 iOS 支持讨论阶段标记发言，并在投票和复盘中带入。
- 已处理：Web 和 iOS 会把讨论阶段盯人目标带入投票阶段，并明确显示“已沿用盯人目标”和“重选”。

### 3.5 揭晓与复盘

现状：

- 复盘展示结算、三项统计、我的判断、投票板、身份结果、AI 目标、关键线索、奖励、局后处理、再来一局、分享、看战绩、回大厅。
- iOS 的 `RevealPanel` 先展示身份列表和结算，`ReplaySummaryCard` 展示解释、我的判断、投票板、身份结果和关键消息。

问题：

- 复盘已回答“我的判断、投票结果、真实身份、为什么对/错”，局后奖励也已放到解释信息之后。
- 高级阵营技能已通过 `skillSummary` 进入复盘，用户可以看到本局哪些任务动作影响了判断。
- 已处理：复盘新增“我的任务结果”，由服务端 `taskResults` 对照任务卡目标和阵营结算给出完成/失败说明。
- 已处理：Web / iOS 复盘新增“复盘校准”，把最终票、信心值和最高怀疑标记对照真实 AI，提示“高信心命中 / 高信心误判 / 判断失准”等结果。
- 已处理：“线索”不再作为阶段名、按钮名或统计名；UI 只在“关键线索”中保留证据含义。
- 已处理：局后处理支持单独拉黑，不强制把避开玩家和举报合并；举报仍可选择“举报并拉黑”。
- 已处理：iOS 复盘把身份结果拆成独立卡片，顺序对齐 Web：胜负原因、我的任务结果、我的判断、复盘校准、身份和证据。

建议：

- 复盘顺序已改为：结果一句话、我的任务结果、我的判断、复盘校准、投票板、身份和 AI 目标、关键证据时间线、奖励和下一步。
- 关键证据时间线必须包含关键发言、我的怀疑标记、中段表态和高级局任务动作。自由追问如需沉淀，应通过证据笔记引用对应发言。
- 奖励卡放在复盘解释之后。主按钮固定为“再来一局”，分享和看战绩为次级。
- “线索”在 UI 中改为“复盘”或“关键线索”，不要单独作为阶段名替代复盘页。

### 3.6 任务与悬赏

现状：

- 首页 tab 有“任务”，局内也有“任务卡”。
- 任务页同时展示推理星、经验、每日任务、背包装扮。

问题：

- 背包装扮属于长期成长或个人资料，不应挤占 **MVP** 的主任务页。
- 今日任务的目标大多是开局、看复盘、开好友房，本质是引导 **core loop**，不需要作为独立主导航。

建议：

- 局外“任务”统一改名为“今日悬赏”。
- 今日悬赏入口放在开局页下方和复盘奖励卡中，不作为底部 tab。
- 背包装扮放入“我的”或 Phase 2 的“背包”二级页。
- 局内“任务卡”改名为“身份任务”，避免和每日悬赏混淆。

- 战绩页也有赛季段位、进度、识别胜率、复盘局数、证据笔记和最近对局。

- 榜单在完成 3 局后逐步露出，或放在战绩页的折叠模块。
- 首页只保留最近一局结果和“看复盘 / 再来一局”。

现状：

- 设置页包含隐私政策、服务条款、社区规范、联系客服、删除账号。

## 4. 局内四个关键概念的真实表达

### 4.1 怀疑程度

真实意义：怀疑程度应该是“玩家自己的判断记录”，不是系统给出的 AI 概率，也不是客观答案。

当前风险：

- 已处理：Web 和 iOS 都只展示玩家自己的“我的怀疑标记”，不展示系统生成怀疑分。
- 已处理：iOS 座位卡显示“我标记 70%”，明确这是玩家自己的判断记录。

建议表达：

- 已处理：文案使用“我的怀疑标记”，不要使用“对他的怀疑度”。
- 已处理：座位卡显示“我标记 70%”或不展示标记。
- 标记动作允许附带一条理由或引用发言。
- 复盘中用它计算 **Suspicion Calibration**：我怀疑的人是否真的可疑，我的信心是否过高或过低。
- 揭晓前不展示任何系统自动可疑分、真实角色推断分或 `strategyTag`。

### 4.2 快捷发言

真实意义：快捷发言应该是降低输入成本的“起手句”，不是一键刷屏，也不是系统替用户做判断。

当前风险：

- 已处理：Web 和 iOS 的三个固定短句只会填入输入框草稿，不会直接发送，用户必须自己按发送。
- 已处理：Web 和 iOS 的对方发言气泡提供“问细节”，点击后引用该句生成输入框草稿，不直接发送。
- “这句太空了”“请给细节”都偏质疑，缺少观察、表态、引用、总结等类型。

建议表达：

- 改名为“起手句”。
- 点击后默认填入输入框，不直接发送；长按或二次确认才发送。
- 按阶段动态提供：
  - 开局：我先听一轮 / 我支持先讲理由 / 这个话题我先站 X。
  - 讨论：请举一个例子 / 你刚才和前一句不一致 / 我暂时怀疑 X。
  - 投票前：我投 X，因为 / 我还不确定，信心中等。
- 已处理：允许引用某条消息生成模板，例如“请补一个具体例子：...”，仍由玩家自己发送。

### 4.3 追问

结论：细节提问不应做成独立功能。玩家已经可以在聊天里直接要求对方给例子、解释前后不一致或说明投票理由；如果再放一个独立按钮，只会和普通发言、证据笔记抢职责。

建议表达：

- 细节提问回归聊天输入和起手句，例如“请举一个例子”“你刚才和前一句不一致”。
- 真正需要系统状态的动作只保留证据笔记、中段表态、最终陈述、投票和高级模式的阵营任务技能。
- 复盘不要展示“提问次数”这种独立指标；应展示关键发言、我的怀疑标记、中段表态、最终票和胜负原因。

### 4.4 任务卡

真实意义：任务卡是私人目标和胜利条件，不是普通说明页。普通找 **AI** 局应显示“侦探任务”；人类卧底等高级阵营局才显示“阵营任务”。

原风险：

- 已处理：任务卡已补齐目标、赢法、工具和禁忌，不再只展示泛化说明。
- 已处理：任务卡不再把“回大厅”作为主动作；局内回看通过顶部“我的任务”入口完成。
- 已处理：Web / iOS 任务卡主标题改为“侦探任务 / 阵营任务 / 诱饵任务 / 伪装任务”，卡内用“任务目标”承接具体目标，不再展示泛化的“你的本局任务”。

建议表达：

- 已处理：名称保持“任务卡”。卡内标题按角色变化：普通局为“侦探任务”，卧底局为“阵营任务”，伪 AI 真人为“诱饵任务”，AI 视角为“伪装任务”。
- 内容固定三到四行：
  - 阵营或任务：侦探 / 人类卧底 / 伪 AI 真人 / AI。
  - 目标：找出 AI，或隐藏身份并撑过投票。
  - 赢法：投票阶段让 AI 成为最高票，或避免 AI 成为最高票。
  - 工具：证据笔记、起手句；高级阵营局额外显示阵营任务技能。
- 任务卡确认后不消失到不可找回，应在局内顶部提供“我的任务”小入口。
- 不建议在任务卡上放“回大厅”作为同级按钮；退出应放在顶部房间菜单，并提示中途退出影响。

## 5. 推荐信息架构

### 5.1 v1.0 推荐主导航

```text
开局
战绩
我的
```

如果好友房被验证为最高增长入口，再测试四 tab：

```text
开局
好友房
战绩
我的
```

不建议 v1.0 使用五 tab。任务和榜单不是独立主路径，应该嵌入 **core loop**。

### 5.2 开局页

```text
开局
├─ 继续上一局
├─ 快速开始：2 人真假局
├─ 推荐模式：3 人猎 AI
├─ 好友房：创建 / 输入邀请码
├─ 最近复盘：看复盘 / 同模式再来
└─ 今日悬赏：有奖励时露出
```

设计目标：用户打开首页后，第一眼只需要判断“继续、快速开始、和朋友玩”。

### 5.3 战绩页

```text
战绩
├─ 个人识别表现
├─ 最近对局
├─ 复盘库
├─ 赛季进度
└─ 排行榜
```

设计目标：所有“我玩得怎么样”的内容集中到战绩页，避免首页被成长系统占满。

### 5.4 我的页

```text
我的
├─ 账号状态
├─ Apple 绑定
├─ 安全与社区规范
├─ 客服与申诉
├─ 背包 / 装扮
└─ 隐私、服务条款、删除账号
```

设计目标：我的页只处理账号、安全、设置和长期资产，不承接核心游戏判断。

### 5.5 局内结构

```text
局内
├─ 顶部：阶段、倒计时、房间菜单
├─ 阶段条：任务 / 讨论 / 投票 / 揭晓 / 复盘
├─ 座位板：身份未知、我的怀疑标记状态
├─ 发言流：消息、引用、用户标证据
└─ 底部动作栏
   ├─ 任务阶段：确认身份任务
   ├─ 讨论阶段：输入、起手句、盯人、证据笔记
   ├─ 投票阶段：候选人、证据、信心、提交/改票
   ├─ 揭晓阶段：翻牌和结果
   └─ 复盘阶段：解释、分享、再来一局
```

设计目标：局内始终是一张“游戏桌”，不是首页卡片的延伸。

### 5.6 复盘页

```text
复盘
├─ 结果一句话：抓出伪装者 / 伪装者逃脱
├─ 我的判断：我投了谁、信心、是否正确
├─ 投票板：每个人投了谁
├─ 身份和任务：所有玩家真实身份、AI 目标
├─ 关键证据：发言、证据笔记、任务动作
├─ 判断校准：为什么猜对 / 为什么误判
├─ 奖励：经验、推理星、悬赏领取
└─ 下一步：再来一局、分享、看战绩、回开局
```

设计目标：用户离开复盘前能清楚说出“我为什么赢/输”。

## 7. 验收标准

可用以下问题做设计验收：

- 新用户完成引导后，是否能在 3 次点击内进入第一局？
- 首页首屏是否只有一个最强主动作？
- 用户在讨论阶段是否能分清“我正在盯谁”和“我最终要投谁”？
- 揭晓前是否完全没有系统泄露的 AI 策略标签、真实角色暗示或自动可疑分？
- 投票后用户是否知道自己投给了谁、能否修改、还剩多久？
- 复盘是否回答了：我投了谁、他是谁、我为什么对/错、哪条发言影响判断？
- 今日悬赏和身份任务是否已经用不同名称区分？
- 战绩、榜单、我的是否不再重复展示同一组等级、XP、推理星和胜率？

外部参考只用于抽象社交推理类产品的常见结构，不建议直接照搬。[狼人杀](https://zh.wikipedia.org/wiki/%E7%8B%BC%E4%BA%BA%E6%AE%BA)类游戏通常围绕隐藏身份、发言、投票、揭晓推进；[Among Us](https://en.wikipedia.org/wiki/Among_Us)类移动社交推理产品也把任务、会议、投票、结果和装扮分在不同层级。图灵迷局应该保留这个“游戏桌优先”的结构，同时突出 AI 识别和复盘解释。
